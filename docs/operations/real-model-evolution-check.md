# Real-model evolution check

Use the short evolution check when validating God → Platform → NPC → Story.
It exercises one dynamic Action and its bound behavior, advances the action to
completion, verifies the conserved world-state change, and runs Story on the
result. It does not simulate a town for days.

Always start the provider check from an **interactive bash** and source the
user environment first. The API key is read by the provider and must never be
printed or written to an artifact:

```bash
bash -ic 'source ~/.bashrc && python scripts/verify_dynamic_evolution.py \
  --provider remote \
  --runtime-dir /tmp/sim2-dynamic-evolution-check'
```

If the provider is unavailable, check only whether the environment variable is
present, without printing its value:

```bash
bash -ic 'source ~/.bashrc; test -n "${MY_MY_API:-}" && echo key-present || echo key-missing'
```

The short check prints a JSON audit containing the God tool calls, the bound
NPC behavior, the public-resource quantity before and after execution, the
carried quantity left on the NPC, and the Story result. Its temporary SQLite
instance belongs under `/tmp/sim2-dynamic-evolution-check*`; do not copy it
into the repository.

For fast local regression, run only the evolution tests:

```bash
python -m pytest -q \
  tests/test_action_binding.py \
  tests/test_npc_evolution_loop.py \
  tests/test_institution_evolution.py
```

The full suite is a pre-merge check, not the per-edit evolution check. The
short tests verify both a valid conserved transfer and rejection/rollback of
an attempted over-transfer.

For a longer evolution audit, use the independent Aster Relay probe. It is a
temporary declarative world generated by the script, so it does not read or
mutate a three-lanterns instance:

```bash
bash -ic 'source ~/.bashrc && python scripts/audit_dynamic_evolution_loop.py \
  --provider remote --rounds 10 \
  --runtime-dir /tmp/sim2-evolution-loop'
```

Each JSON line is one full round. The probe starts with one unresolved archive
and a depleted public reserve. God must create the first conserved supply
Action and bound BT; later, two research work outcomes wake God to create a
new source. NPC uses the same generic research BT on each new source, and
Story receives the actual outcome event. The JSON records new entities,
registered definitions, NPC choices, Story beats, resource quantities and
the retained story state. The SQLite file and `evolution-audit.jsonl` stay
under the supplied runtime directory.

### Final 10-round causal audit after the observation fixes

The following runs were kept as evidence while fixing the first failure, not
silently discarded:

1. `/tmp/sim2-evolution-loop-after-event` reached the first supply and
   research chain, then entered a false loop. `inspect_archive` emitted
   `object.recovered` because an information Action with `object_id` defaulted
   to recovery. The generic default is now observation; recovery requires
   `record_object_discovery: true`.
2. `/tmp/sim2-evolution-loop-after-observation-fix` removed that false event,
   but correctly exposed a second gap: after the model exhausted the only
   research question, repeated inspections changed `relay_stability` without a
   configured world signal, so God waited and the NPC repeated inspection.
3. `/tmp/sim2-evolution-loop-rule-audit` uses a declarative
   `relay_stability_review` world rule in the probe. The rule is a generic
   threshold signal, not Platform code. It converts the verified stability
   change into a God task and lets the next research source be created through
   the normal proposal path.

The final run completed all ten rounds and wrote
`evolution-audit-summary.json` with `{"status": "passed", "flags": []}`.
The causal observations were:

- Round 1: God created a conserved supply Action and bound BT; Mira executed
  it and the public reserve changed from `0` to `1`.
- Round 3: the generic research BT completed the configured archive stage;
  the behavior outcome and `research.completed` event both reported
  completion.
- Rounds 4, 6 and 8: God created new, non-duplicate research entities from
  accumulated evidence; Mira selected the same generic research BT for each.
- Story accepted new beats for the new source facts. When a new event did not
  justify a distinct continuation, Story returned `wait` rather than adding a
  duplicate beat.
- No LLM error, rejected intent, false recovery event or standalone Action was
  observed. The last round had a valid God `wait` because the next proposed
  research key would duplicate an existing source, while the world still had
  a completed Story thread and no unsupported mutation.

The complete per-round context summary, tool arguments, NPC outcome, Story
result, new objects and story state are in
`/tmp/sim2-evolution-loop-rule-audit/evolution-audit.jsonl`. The run was
started with `bash -ic 'source ~/.bashrc && ...'`; no credentials or proxy
settings were written to the log.

The post-fix verification also passed `397` tests and `compileall`. The
1,000-agent platform benchmark completed five runs with p95 tick time
`143.422 ms` (warm-up excluded), with no failed agents.
